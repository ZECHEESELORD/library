# Migration Notes

## v13.1

- `camera` gains a first-person arm-pose channel: twelve `CameraChannel`s (`ARM_MAIN_X` to `ARM_MAIN_ROT_Z`, `ARM_OFF_X` to `ARM_OFF_ROT_Z`) that sum per hand into an `ArmPose`. `LayerSample` and `LayerState` gain `mainArm` and `offArm` components, `ReducedRules` gains `armScale` (1 in both stock profiles) and `SafetyLimits` gains `maxPitch` (85), `maxArmOffset` and `maxArmRotation`; the v13 constructors still compile and give identity arms. A pitch curve that is not unwound now clamps total pitch at 85 instead of 90. Telemetry adds twelve `camera.arm_*` columns.
- `camera-fabric-client` adds a mixin into `FirstPersonHandsAndItemsRenderer.submitArmWithItem` (after its `PoseStack.pushPose`) that moves each hand and its item by the live pose about the hand's rest position, and draws the empty off arm while its pose is live. With no arm cue live it writes nothing, so the hands stay exactly vanilla.
- `movement-api`: `MoveOutput` gains a last component `cancelSprint` (the 15-argument constructor still compiles), `MoveEvent` gains `FallDistanceCap`, and `MoveKeys.MANTLE_REFUSAL` names the refusal passive. Telemetry adds `move.jump_press_ticks` (each jump press's length, written on its release tick).
- The stock moves follow the 2026-11-23 movement rulings, and the tuning files changed shape. A game that keeps its own tuning folder must merge the new defaults: `mantle.json` is rewritten (vault and climb windows, sprint gate, approach angle, long-fall limit, hop, buffer, strafe, the climb and vault camera keys, arm keys and the `refusal` block); `jump.json` drops the hard-landing shake keys for `landingMinFall`, `landingDipBase`, `landingDipPerBlock`, `landingDipMax`, `landingDipTicks`, `landingRecoverTicks` and a `stumble` block, and `moveScale` for preset B is now 1.0; `slide.json` drops `cooldownTicks`, `maxFlatTicks` and the downhill keys for `refillTicks`, `slopeGain`, `maxSpeed`, `endSpeed`, `maxAirTicks` and the camera's `fovMin`; `roll.json` adds `sideMinDegrees`, `sideMaxDegrees` and `sideRoll`; `wall_jump.json` adds `endFall`, `maxBrake` and `roll` to the slide.
- Behaviour changes a game will notice: a walking tap jump at a 1-block step is the vanilla jump (only a sprint vaults it); the vault keeps its speed; mantles never trigger after a fall over 6 blocks or from the look alone; a blocked ledge plays a slap instead of nothing; boost needs a fresh press; landings under 1.3 blocks have no dip and hard landings stumble instead of shaking; sideways and backward rolls never turn yaw; the slide ends on a speed floor and is never refused; the wall slide no longer resets fall distance but caps it at the equivalent height of its fall speed, on client and server.
- Follow-up fixes to those rulings, also noticeable in play: the free tick after a vault, a climb exit or a mantle hop moves at exactly the ruled exit speed (0.2806 for a sprint vault or climb, 0.2159 for a walking climb, exit + 0.1 for a hop), because the move now zeroes vanilla's input push on that tick instead of letting it stack; the 6-tick stumble after a hard landing clamps horizontal speed to vanilla walking speed as well as cancelling sprint; a refused mantle blocks the wall slide until the body touches the ground again (a wall kick still works); and the client caps the wall slide's fall distance after `travel`, in the same order as the server, so client and server agree and the landing dip reads the capped fall. `ReferenceIntegrator` gains `inputAcceleration` and `groundSpeed`, and `MantleRefusal.REFUSED` is the engine-memory key of the last refusal tick.
- An empty moveset is still exactly vanilla.

## v13

- New client-first feel modules for the Fabric lane: `telemetry` (`-api`, `-core`, `-fabric`, `-fabric-client`), `prediction` (`-api`, `-core`) and `net` (`net-fabric`, `net-fabric-client`).
- Fabric mods that declare a `net` feature need the same library version on client and server. The server checks it, and each declared feature's protocol version, in the configuration phase; a mismatch disconnects and names the feature. With no feature declared, the handshake is skipped and vanilla clients join as before. Library payload ids are `creative_library:<feature>/<name>`.
- `tween-api` adds keyframe tracks (`Track`, `LayeredTrack`, markers), springs (`SpringSpec`), seeded smooth noise, signal channel specs and generators (overshoot, anticipation, squash and stretch); `tween-core` adds the stateful `Spring`, `Vec3Spring`, `SignalChannel` and `SeekableSampler`. `Easing` gains `BACK_OUT`, `BACK_IN_OUT`, `ELASTIC_OUT` and `BOUNCE_OUT` (an alias of the existing `BOUNCE`, which already eased out) and now implements the new `EasingFunction`. Existing `Tween` and `Envelope` callers need no change.
- `spatial-api` adds a `Quaternion` value type.
- New `camera` feature (`camera-api`, `camera-core`, `camera-fabric-client`): a client-first camera rig with keyed, cancellable cues on additive pitch, roll, FOV, eye-height, shake and look-scale channels, signal layers, trauma shake, a Full or Reduced option (`config/creative_library_camera.properties`) and `camera.*` telemetry columns. With no live cue the vanilla camera is untouched. One camera service is open at a time (`FabricClientCamera.open()`).
- Camera eye-height curves can be absolute (`ChannelCurve.absoluteEyeHeight()`, `"absolute": true` in cue JSON): the curve is the drawn eye height above the feet, resolved each frame against the host camera's own eased eye height (`ViewInput.eyeHeight`, a new record component; the four-argument constructor leaves it unknown). While one is live the Fabric adapter holds vanilla's eye-height easing at the body's eye. `ChannelCurve.absoluteEyeHeightFrom(eye -> curve)` builds the curve from the eye height the camera last drew when the cue starts, so a move starts where the camera already is (`StandardCameraRig.drawnEyeHeight()`, cleared by `skipFrame()`); `ChannelCurve` gains a `fromEye` component. `LayerSample` and `LayerState` gain an `eyeTarget` component (NaN when none) and telemetry adds `camera.eye_target`. The movement roll and slide use both (the slide exit no longer takes a start height), and `EyeCompensation` is removed.
- New `hot-reload` feature (`hot-reload-api`, `hot-reload-core`): watched JSON data files swapped in at a tick boundary. `CameraCueCodec` decodes camera cues for it.
- New `devtools-fabric-client`: a deterministic capture clock for dev builds (`CaptureClock`, `CaptureTimes`), enabled in a development environment or with `-Dcreative_library.devtools=true`.
- New `movement` feature (`movement-api`, `movement-core`, `movement-fabric`, `movement-fabric-client`): moves as pluggable abilities over vanilla physics, five stock moves at the tunings in design doc 02, one JSON tuning file per move (hot-reloaded from a folder the server names, for example `config/creative_library_movement/`), server-checked claims (`creative_library:movement/*`, protocol 1), and `move.*` and `body.*` telemetry columns. `movement-fabric` mixes into `Avatar.getDefaultDimensions`, `Player.updatePlayerPose` and `LivingEntity.causeFallDamage`; `movement-fabric-client` into `LivingEntity.aiStep` and `getEffectiveGravity`, `KeyboardInput.tick` and `Camera.alignWithEntity`. Every hook is a no-op while no moveset is enabled, so a game that never opens `ServerMovement` or `ClientMovement` is unchanged; a server with `ServerMovement` open declares the `movement` feature, so its clients need the client mod.
- `movement-api` `InputFrame.keys("FSN")` parses held keys from letters.
- `camera-motion` and `screen-overlay` are unchanged and remain the server-side camera and overlay tools for Paper and Minestom.

## v12

- Paper consumers on the latest lane move to Paper/ShreddedPaper `26.3` (`api-version: '26.3'`). Servers still on `26.2` should stay on v11 or use the retained `1.21.11` lane.
- `entity-paper` now requires the PacketEvents `2.14.0` server plugin. `PaperEntityPlatform` rejects `2.13.0` and any protocol other than `V_26_3`.
- Minestom adapters are `compileOnlyApi` on Minestom `2026.10.07-26.2` (Minecraft `26.2`). Minestom has no `26.3` build yet, so `26.3` clients cannot join Minestom servers. It brings Adventure `5.2.0`; `ClickEvent.value()` is replaced by a typed `payload()`, `Block.isAir()` is now `Block.air()` (likewise solid and liquid), and building an `ItemStack` needs bound registries (`MinecraftServer.init()`), which matters for consumer unit tests.
- `message-velocity` and `data-velocity` are compiled for Java 25 against Velocity API `4.3.1`. Consumers need a Java 25 toolchain and a Velocity 4.x proxy. Velocity API `4.x` resolves from the PaperMC repository (`https://repo.papermc.io/repository/maven-public/`); `repo.minebench.de` and Maven Central do not host it, so proxy consumers that added only minebench must add PaperMC. The move from Velocity API `3.x` to `4.x` is a major host-API change for the consumer's own plugin code, and it brings Adventure `5.2.0` (v11's Velocity API brought `4.17.0`), which also lifts the common modules' `adventure-api` to `5.2.0` on a Velocity classpath. Consumer Adventure code meets the same breaks as on Minestom: `ClickEvent` is now generic and `ClickEvent.value()` is replaced by a typed `payload()`. The library API did not change.
- Latest-lane Fabric mods now require Fabric Loader `0.20.1` or newer and `fabric-api` `0.166.2` or newer. The retained `1.21.11` lane keeps its v11 runtime requirements (Loader `0.18.6` or newer, any `fabric-api`); it is now built against Fabric API `0.141.6+1.21.11`.
- Shared dependencies that reach consumers moved: the common `-api` modules expose `adventure-api` `4.26.1` (was `4.17.0`), and because it imports `adventure-bom` `4.26.1`, Gradle also aligns sibling Adventure modules (for example the copy a Fabric mod bundles, or the Adventure behind `adventure-platform-bukkit` in `message-paper-1_8_8`) up to `4.26.1`. `data-mongodb` exposes `mongodb-driver-sync` `5.15.0` (was `5.1.4`), and `data-core` ships `caffeine` `3.3.1` (was `3.1.8`) at runtime. Consumers that pin or shade older versions of these should re-check them. The library API did not change.
- `message-paper-1_8_8` is now compiled for Java 21 instead of Java 25, so Spigot 1.8.8 servers and Gradle consumers on Java 21 can load and resolve it. It still needs a Java 21 runtime.
- The `minestom-example` harness port can be overridden with `-Dminestom.example.port=<port>`, either on `./gradlew runMinestomExample` or when launching the main class directly; the default is still `25565`.

## v9

- The NPC behavior expansion is a source-breaking v9 re-release. Paper now uses native mannequins and requires PacketEvents `2.13.0`; the Citizens adapter, repository, dependency, settings, and examples have been removed completely.
- Entity interactions now use `EntityInteractionAction` (`USE` or `ATTACK`), an optional `InteractionHand`, and an `EntityInteractionResult` (`PASS` or `CONSUME`). Use `EntityInteractionHandler.observing(...)` when migrating a former void observer lambda.
- `PLAYER_LIKE_HUMANOID` exposes `HumanoidBehaviorCapable` on Paper and Minestom. Behavior remains opt-in: a mannequin without an `NpcBehaviorProfile` is inert, and explicit behavior commands fail fast until configured.
- Paper entity creation, service creation, teleport, and cleanup have asynchronous Folia-safe entry points. Synchronous entry points are owner-region fast paths and fail clearly from a foreign lane.

For a former void interaction observer, return an explicit result or use the migration helper:

```java
.interactionHandler(EntityInteractionHandler.observing(
        context -> audit(context.interactor(), context.action(), context.hand()),
        EntityInteractionResult.PASS
))
```

`USE` always carries `MAIN_HAND` or `OFF_HAND`; `ATTACK` carries no hand. Application handlers still receive both actions after behavior observes them. Safe native mannequins consume both actions and suppress vanilla damage and knockback, while generic entities remain `PASS` by default.

Replace any dependency or construction of the removed Paper Citizens adapter with `entity-paper` and `new PaperEntityPlatform(plugin)`. Install PacketEvents `2.13.0` as a server plugin and declare it as a required dependency. On Paper/Folia, migrate lifecycle calls to `spawnAsync`, `spawnServiceAsync`, `teleportAsync`, and `closeAsync` unless the caller is already on the owning region lane.
- YAML deleted-document revisions are now durable across restart. `WriteCondition.revision(...)` can safely guard delete-then-recreate flows after the owner restarts.
- Mongo initialization is now lazy on first async operation instead of forcing `ping` and revision-index setup during owner startup.
- Mongo insert retries now treat only duplicate-key insert failures as retryable conflicts. Other write failures surface immediately.
- Owned YAML and Mongo executors now close with a bounded graceful drain before falling back to forced shutdown.
- Velocity data owner now closes its `DataApi` during proxy shutdown.
- Minestom shared-owner registration now uses a JVM-global registry instead of a classloader-local static map.
- Compiled menu validation now resolves only the initial frame during build. Other frames validate lazily on first access.
- Paged and tabbed compiled menus now keep lazy frame-id sets instead of materializing every frame id up front.
- Reactive placement compilation is now bounded and keyed by visual state plus prompt labels, so visually identical items can reuse compiled presentation without pinning stale interactions.
- Paper and Minestom menu renderers now use bounded visual-state caches instead of unbounded `MenuSlot` caches.
- `stateFactory(...)` is now the only stateful reactive initializer; the shared-instance `state(...)` entry point has been removed so stateful menus can create fresh state for each session.
- Reactive reducers now return one of `ReactiveMenuResult.unchanged()`, `effect(...)`, or `update(...)`, with at most one control effect. The former `stay(...)`, `of(...)`, and multi-effect result shapes have been removed.
- Reactive canvas item movement now uses fixed `custodyTarget(...)` declarations plus a `custodyPolicy(...)`. Platform adapters own exact native-stack custody, accept only whole-stack movement, reject occupied destinations, return outside clicks to the origin, and report committed or rejected outcomes to reducers.
- Menu navigation, prompts, close, disconnect, and shutdown attempt to settle held custody before changing lifecycle state when the host still permits owner-thread work. If native ownership cannot be proven, adapters retire or tombstone their claim instead of crediting another copy; this no-dupe-first behavior may lose an item. Hard-crash exactly-once recovery remains outside the non-journaled runtime contract. Folia hot-disable or reload with active Paper menu sessions is unsupported.
- Lifecycle calls made reentrantly from a reducer, renderer, custody policy, or lifecycle callback are fenced and deferred to the next owner tick. Stale callback results are discarded before native inventory mutation, effects, or rendering; callbacks should still remain synchronous and side-effect-free.
- Back history is now a bounded menu-to-menu breadcrumb trail. Frame, page, and tab changes no longer create Back entries.
- Unchanged reactive results no longer trigger native rendering. Work for changing views still depends on their tick interval and rendered content. High-frequency reactive menus should keep titles stable because Paper and Fabric rebuild and reopen the native inventory when the title changes.
- Audited Minestom runtime adapters now fail fast when a supposedly owned-thread future is still incomplete instead of blocking that thread with `.join()`.
